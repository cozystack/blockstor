# CLI parity known deltas (accept-list)

Generated parity reports (`tests/operator-harness/cli-parity-refresh.sh`) fail CI when they discover a non-`PARITY` row that is **not** listed in this file. Each row here represents a delta we accept as documented divergence between blockstor's REST surface and upstream LINSTOR.

When you add or change a CLI verb or wire shape:

1. Run `cli-parity-refresh.sh` against the dev stand.
2. If a new non-`PARITY` row appears that is intentional (work-in-progress feature, downstream-only enrichment, etc.), append a row to the table below with justification.
3. If the new row represents an unintended regression, fix the controller — do **not** add it to this file.
4. `accepted_until` is either an ISO date (review by then) or `permanent` (intentional divergence forever).

Row IDs match the command-catalogue indexes used by `cli-parity-refresh.sh` (see the `COMMANDS` heredoc in that script). Either match by `# id` or by command-string + tag — both forms are honoured by the whitelist grep.

| 67 | `r c <node> <rd>` (StorPoolName resolution chain) | BEHAVIOR | permanent | Corner D5: upstream resolves the pool via VD → Resource → RD → Node → literal `DfltStorPool`. | 68 | `controller set-property BalanceResourcesEnabled` (periodic balancer) | BEHAVIOR | 2026-12-31 | Corner D6 (linstor-administration.adoc ~887-907). Upstream ≥1.26.0 runs a periodic BalanceResources task (default interval/grace 3600 **seconds**) that tops replica counts back up to the RG place-count and TRIMS replicas restored by snapshot rollback (~2518-2521); disabled via `BalanceResourcesEnabled` (RD > RG > controller). BS has its OWN equivalent — the `RGRebalanceReconciler` (`internal/controller/rg_rebalance_controller.go`) — wired through reconcile-driven redundancy convergence (annotation-driven refill + scheduled tick + spawn-shortfall replay + node-offline grace gate). The `BalanceResourcesEnabled=false` kill-switch is honored at controller scope (`balanceResourcesDisabled`). Residual divergences accepted here: (1) BS interprets `BalanceResourcesInterval`/`GracePeriod` as **minutes**, upstream as **seconds** (`DefaultBalanceResources*Minutes`); (2) BS is strictly ADDITIVE — it never TRIMS over-placed replicas, so the snapshot-rollback trim side effect is absent (BS leaves the operator's `r d` as the only scale-down path); (3) BS's `controller properties/info` catalogue does not surface the BalanceResources keys at controller scope (it does at RG/RD scope). The property surface itself is accept-inert and matches upstream verbatim. Pinned by `TestCornerD6_BalanceResources*` (L1 REST) + `TestRGRebalanceReconcilerHonoursBalanceResourcesDisabled` (L1 controller). |
| 69 | `rd c --layer-list <bad>` (negative-case envelope) | WIRE_SHAPE | 2026-12-31 | Corner D7b (linstor-administration.adoc ~1819-1833). Invalid order (`luks,drbd,storage`), duplicate layer (`drbd,drbd,storage`) and unknown layer (`bogus`) are all REJECTED by both controllers at RD-create time — the OUTCOME matches. Divergences: (a) the error-envelope wire shape — upstream emits `The layer stack [...] is invalid` + `error_report_ids` + `obj_refs.RscDfn` (rc=10); BS emits a plain typed APICallRc message naming the specific fault (`invalid layer order: …` / `layer X appears more than once …` / `unsupported layer: …`, HTTP 400) with no error-report id. (b) The unknown-layer case is rejected CLIENT-side by python-linstor (`Layer name "bogus" not valid`, exit 2) so the controller never sees it via the CLI; BS's server-side allowlist still refuses it for a raw REST caller. (c) BS validates layer order at BOTH `rd c` and `rg c` (BLOCKSTOR_STRICTER); upstream validates only at `rd c`/spawn and ACCEPTS a bad `rg c --layer-list` (oracle 2026-06-04: `rg create … luks,drbd,storage` → SUCCESS). Pinned by `TestCornerD7b_*` (L1) + `tests/e2e/cli-matrix/rd-c-layer-list-rejected.sh` (L6). |

| 70 | `rd lp <rd>` (inherited parent-scope props shown inline) | WIRE_SHAPE | permanent | Corner-case I2. Upstream LINSTOR treats inheritance as a *reference, not a copy*: a property set on a resource-group / controller affects existing children, but the child's `list-properties` does NOT show the inherited key inline (UG9 ~4587: "As the QoS properties are inherited and not copied, you will not see the property listed in any child objects").
